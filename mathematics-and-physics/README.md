# Engineering AI — نموذج ذكاء هندسي نملكه وندرّبه من الصفر

هذا فرع تجريبي لتطوير ذكاء اصطناعي خاص بمشروع بوت تلغرام في مجالات الرياضيات والفيزياء وهندسة البرمجيات والإلكترونيات.

## الفرق الجوهري عن الإصدار السابق

**لا نعتمد على أوزان نماذج جاهزة، ولا على Ollama أو OpenAI API.** أعدنا استخدام كود معمارية Transformer من مشروع nanoGPT المرخص MIT، مع الإبقاء على نسب المصدر وترخيصه في `engine/LICENSE.nanoGPT`، وحذف مسار استيراد الأوزان المدرّبة مسبقًا. ننشئ الأوزان عشوائيًا وندربها على مجموعتنا النصية.

**تنبيه علمي:** وجود الكود لا يساوي امتلاك معرفة؛ مجموعة البيانات المرفقة صغيرة جدًا وهي لإثبات آلية التدريب فقط. بعد التدريب التجريبي سيكون الناتج نموذجًا محدودًا، قد يعيد نصوصًا غير مفهومة وقد يجيب خطأ. لا يمكنه الآن الإجابة عن جميع الأسئلة الهندسية، ولا يجوز استخدامه لاتخاذ قرارات هندسية حساسة. للوصول إلى جودة عالية نحتاج بيانات عالية الجودة وكبيرة، موارد GPU، تقييمات صعبة وتحسين متكرر.

## مكونات المشروع

- `engine/model.py`: نسخة معدلة من nanoGPT (MIT)، Transformer مبني على PyTorch.
- `engine/tokenizer.py`: ترميز UTF-8 بايت، 256 رمزًا، من تنفيذنا بلا قاموس جاهز؛ مناسب كبداية لكنه غير كفؤ للعربية.
- `engine/train.py`: تدريب النموذج من أوزان عشوائية، مع تقسيم بيانات وتسجيل loss على التحقق وحفظ checkpoint.
- `engine/inference.py`: تحميل **checkpoint المحلي الخاص بنا فقط** وتوليد نصوص.
- `engine/evaluate.py`: تقييم أولي مبسط، ليس قياسًا شاملًا للجودة.
- `datasets/engineering.txt`: بيانات تدريب صغيرة للغاية.
- `datasets/eval.jsonl`: أمثلة اختبار توضيحية **تتداخل مع التدريب**، ولذلك لا يجوز اعتبار نتيجتها مقياس تعميم. يجب إعداد مجموعة تقييم مستقلة قبل مقارنة النماذج.
- `storage.py`: PostgreSQL لتسجيل تقدم الطلاب والمحادثات.
- `bot.py`: واجهة Telegram التعليمية.
- `docker-compose.yml`: تشغيل PostgreSQL والبوت وخدمة تدريب اختيارية.

## تجهيز البيئة

تحتاج Docker Desktop أو Docker Engine وCompose، ورمز بوت من [@BotFather](https://t.me/BotFather). يلزم اتصال بالإنترنت لتنزيل الاعتماديات أول مرة وللاتصال بخدمات Telegram، لكن الحسابات والتوليد لا تستخدم أي مزود نماذج خارجي.

```bash
git clone https://github.com/waleed875/tel01.git
cd tel01
git checkout feature/from-scratch-engineering-ai
cd mathematics-and-physics
cp .env.example .env
```

على Windows PowerShell استخدم `Copy-Item .env.example .env` بدل `cp`. افتح `.env` وعدّل `TELEGRAM_BOT_TOKEN`، واستخدم كلمة مرور قوية في `POSTGRES_PASSWORD`. لا ترفع `.env` إلى GitHub.

## التدريب قبل تشغيل البوت

```bash
docker compose build
docker compose --profile train run --rm trainer
```

سيتم إنشاء أوزان جديدة في volume باسم `trained_models`، ويحفظ الملف `checkpoint.pt`. التدريب الافتراضي نموذج صغير وتجريبي (4 طبقات، 128 بعدًا، 300 خطوة)، وليس تدريبًا هندسيًا حقيقيًا كافيًا. CPU ممكن لكن قد يكون بطيئًا.

ثم شغّل البوت وقاعدة البيانات:

```bash
docker compose up -d postgres tutor
docker compose ps
docker compose logs -f tutor
```

أرسل `/start` في محادثة البوت. إذا لم تتوفر أوزان صالحة فستفشل إجابات التوليد مع رسالة توضيحية، بينما تبقى الاختبارات الثابتة متاحة.

يمكن تجربة تقييم النموذج، داخل حاوية التدريب، باستخدام:

```bash
docker compose --profile train run --rm --entrypoint python trainer -m engine.evaluate --checkpoint /app/models/checkpoint.pt --benchmark /app/datasets/eval.jsonl
```

لكن أرقام التقييم الحالية غير صالحة لقياس التعميم؛ أنشئ تقييمًا منفصلًا غير مستخدم في التدريب.

## كيف نطوره إلى نموذج هندسي قوي؟

1. **إدارة البيانات والتراخيص:** جمع نصوص ومناهج وأمثلة ومسائل وحلول صحيحة ومصرّح باستخدامها؛ إزالة التكرار والبيانات غير الدقيقة.
2. **ترميز أكثر كفاءة:** تدريب tokenizer جديد على العربية والإنجليزية والمعادلات والبرمجة؛ هذا يتطلب إعادة تدريب النموذج منذ البداية.
3. **توسيع التدريب:** اختيار حجم النموذج وفق ذاكرة GPU وميزانية الحوسبة، ومراقبة loss ومقاييس التعميم.
4. **تعلم الإجابة:** إعداد مجموعات سؤال/جواب ومهام شرح هندسي حقيقية، وليس النص العام وحده.
5. **اختبارات تحقق:** مسائل جديدة لم يسبق رؤيتها، تحقق رمزي/عددي، سلامة الإلكترونيات، اختبارات برمجية داخل بيئة معزولة.
6. **مصادر موثقة:** ربط النسخة المدربة بالكتب والوثائق المحلية بنظام بحث مع مراجع، مع عدم الخلط بين مصادر المعرفة وتدريب الأوزان.
7. **العمل المستمر:** نسخ متعددة من النماذج وإصدارات البيانات، ومنهج يراعي مستوى الطالب ويقيس تقدمه في PostgreSQL.

## الأمان والحدود

- لا تُعرض PostgreSQL على الإنترنت؛ البوت يستخدم Telegram long polling.
- لا تشغّل checkpoint مجهول المصدر: ملفات الأوزان يجب أن تكون ناتجة عن تدريباتك أنت.
- احتفظ بنسخة احتياطية من بيانات PostgreSQL ونسخ نموذجك المدرب منفصلة عن المستودع.
- أمر `docker compose down` لا يمسح الـ volumes، لكن `docker compose down -v` يحذفها.
- نموذجنا الحالي **نصي فقط**، ولا يوجد دعم للصوت أو تحليل الصور أو تنفيذ الكود.
- لا يمكن الجزم بعمل الإصدار في بيئتك دون إجراء اختبار Docker فعلي.
